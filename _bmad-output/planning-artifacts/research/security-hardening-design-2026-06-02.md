## Decisions taken (product calls confirmed with user 2026-06-02)

- **Tool posture (REFINED 2026-06-02 per user):** _fine-grained allowlists, not a blunt toggle._ The product purpose (read legacy source + git history to extract knowledge/patterns) needs **safe read-only shell commands** (`grep`, `ls`, `find`, `cat`, `head`, `tail`, `wc`, `tree`) and **read-only git** (`log`/`show`/`diff`/`blame`/… — history yes, commit/push no) and **websearch**, but NOT arbitrary shell or unrestricted web. Verified the SDK/opencode supports this natively (sources below):
  - **bash = command-pattern allowlist** (`bash?: { [pattern]: "allow"|"deny" }`, `gen/types.gen.d.ts:859`). opencode's shell tool _parses the command tree_ and matches each command via `Wildcard.match` (`permission/index.ts:185`), so `{ "grep*":"allow", "ls*":"allow", "find*":"allow", "cat*":"allow", "git log*":"allow", …, "*":"deny" }` allows the read-only extraction commands and denies everything else (incl. `curl|sh`, `rm`, package installs, `cat /etc/...`). The git policy is a **read-only-subcommand allowlist** (commit/push/config denied by default) — see the dedicated bullet below. Default allowlist ships curated; consumer can extend via an input.
  - **websearch = allow** by default (knowledge extraction legitimately needs it; it returns search results, not arbitrary fetch of attacker URLs).
  - **webfetch = per-domain allowlist IS achievable (REVISED 2026-06-02 after deeper research — `webfetch-domain-allowlist-research-2026-06-02.md`).** Earlier "not possible" was wrong: it was based on the SDK _config type_ only. The webfetch tool submits the URL as a permission `pattern` (`webfetch.ts:39`) and the engine matches per-URL via `Wildcard.match` — so per-domain rules work at runtime. The catch: the _documented_ `Config.permission.webfetch` is typed tri-state `Action` and an object form **crashes strict decode** (don't put it in `opencode_config`). The working lever is the **`OPENCODE_PERMISSION` env var**, which is `JSON.parse`'d and merged _after_ schema validation and never re-validated (`config.ts:748`), so the object form survives:
    ```
    OPENCODE_PERMISSION='{"webfetch":{"https://github.com/*":"allow","https://www.google.com/*":"allow","*":"deny"}}'
    ```
    The SDK spreads `...process.env` into the spawned `opencode serve`, so the Action just sets this env var (allow-globs first, `"*":"deny"` last — `findLast` precedence). **Architect decision:** ship a default-deny webfetch with a **`webfetch_allowed_domains` input** (e.g. `github.com,www.google.com`) that the Action compiles into the `OPENCODE_PERMISSION` webfetch rules; empty input ⇒ webfetch fully denied. **Risk mitigation (mandatory):** this rides a type-hidden runtime behavior, so (1) add a **smoke test** asserting an off-allowlist URL → `DeniedError` and an allowlisted URL succeeds — gate the feature on it; (2) tie re-verification to Epic 12's **SDK-currency guard** (re-check on every opencode bump); (3) **fallback = Option B** (`tool.execute.before` plugin that parses `args.url` hostname and throws off-allowlist — fully auditable, type-quirk-independent) if the env-merge behavior ever breaks. Pair with consumer egress filtering (harden-runner) as defense-in-depth (documented in 13-7). **Scope note:** set `OPENCODE_PERMISSION` only for `webfetch` (it `mergeDeep`s across all keys — keep bash/external_directory/etc. in the documented `opencode_config` where their object forms are type-valid, so we don't duplicate or clobber).
- **Filesystem confinement (REFINED 2026-06-02 per user — stronger fix for AGENT-02/03):** confine the agent to the **GitHub runner working directory** (or a configurable subdir) only. Verified opencode enforces this via the **`external_directory` permission**: any read/bash path NOT inside the project directory (`containsPath(full, instance)`, `tool/external-directory.ts:30`) triggers `external_directory`. Set **`external_directory: "deny"`** and the agent cannot read `auth.json` (`~/.local/share/opencode/`), `/proc/*/environ`, `~/.aws/credentials`, or anything outside the root — this directly closes the on-disk credential reads that env-scoping alone could not (supersedes the weaker "relocate HOME/XDG" A3).
  - **bash is ALSO directory-confined** (REFINED per user "limit the directory bash can act on"): opencode's shell tool _parses each command's path arguments_ into `scan.dirs` (`tool/shell.ts:191 pathArgs`, `:267 ask`) and raises `external_directory` for any dir outside the root. So `external_directory: "deny"` confines **both reads and bash** — `cat /etc/passwd`, `grep -r /root`, `ls ~/.aws` are all refused because the path arg resolves outside the project root. No separate mechanism needed.
  - **The confinement root is settable by the Action** (not hardcoded to cwd): the SDK client takes `createOpencodeClient({ directory })` which sets the `x-opencode-directory` header → becomes `ctx.directory` (`sdk/client.js:43-50`). Default it to `GITHUB_WORKSPACE`; expose an optional `agent_working_directory` input so a consumer can scope bash/reads to a **subdirectory** of the repo (e.g. `/github/workspace/legacy-src`) for tighter confinement.
  - **Worktree gotcha to guard:** `containsPath` also matches `ctx.worktree`; for **non-git** projects opencode sets `worktree="/"` which would match ANY path — but opencode already special-cases this (`if (ctx.worktree === "/") return false`, `instance-context.ts:21`), so confinement holds. Story 13.2 must add a test that a non-git workspace still rejects out-of-root paths (don't regress this guard).
- **baseURL policy:** allowlist + `allowed_provider_hosts` opt-in input, https-only, block private/metadata ranges, AND refuse `auth.set` for non-allowlisted endpoints (research B1+B2).

## Architecture alignment (architecture.md)

- **Reuse the existing allowlist pattern.** `validation.ts:buildChildEnv` already scopes the validation child env to an allowlist. RC-A's agent env-scoping must extract this into a **shared helper in `security.ts`** (the designated home for "path, secrets" per the module table) so the two paths can't drift. This honors the "Child processes — isolated env" row already in architecture.md's Security Architecture table.
- **`security.ts` stays a leaf module.** The new helpers (env allowlist, baseURL validation, host allowlist constant) live in `security.ts` (or a new `src/permissions.ts` leaf if `security.ts` grows too large — architect call during story creation). No new circular deps.
- **Result pattern / fail-closed.** baseURL rejection and validation failures use the existing early-return error path (`config.ts`/`security.ts` throw → caught → sanitized), consistent with the Error Handling Strategy table.
- **Layered timeouts.** MEDIUM-1's global deadline slots into the existing "Timeout Architecture" hierarchy as the missing top-level **Workflow** wall-clock enforcer (the table already lists "Workflow 30min" as a layer — it just wasn't actually enforced).

## Per-finding design (what to build, where, what to preserve)

### RC-A — agent containment (CRITICAL; covers AGENT-01/02/03/06/09, FINDING-5, HIGH root-bash, RCE)

Layered, all in scope:

- **A1 env scoping** — shared `buildScopedEnv()` helper in `security.ts`; sanitize `process.env` to allowlist around `createOpencode` in `opencode.ts:doInitialize`, restore in `finally`. Allowlist: PATH/HOME/LANG/TERM + runtime vars (JAVA*HOME, GOPATH, GOROOT, XDG*\*) + declared `env_vars` + RUNNER_TEMP. **Preserve:** env-authenticated providers (fact #2) — keep declared env_vars; don't strip runtime vars or Java/Go LSP autoinstall breaks.
- **A2 fine-grained bash allowlist + websearch allow + webfetch opt-in + fix merge** — rewrite `buildPermissionConfig` to:
  - **bash = command-pattern allowlist** (object form): ship a curated default allowing read-only extraction commands (`grep*`, `ls*`, `find*`, `cat*`, `head*`, `tail*`, `wc*`, `tree*`, `file*`, `rg*`) with a final `"*": "deny"`. Add an input (e.g. `bash_allow_patterns`) for consumers to extend. Deny everything not matched (blocks `curl|sh`, `rm`, installs, writes, `cat` of out-of-tree paths — the last is also caught by `external_directory`).
  - **git = read-only-subcommand allowlist (REFINED 2026-06-02 per user "allow git so the agent can read history, but NOT commit/push by default"):** opencode matches git **at the subcommand level** — `BashArity` treats `git` as arity 2, so `git log` / `git show` / `git config` are _distinct_ permission patterns (`permission/arity.ts`). So we allow the history/knowledge subcommands and deny the rest:
    - **ALLOW:** `git log*`, `git show*`, `git diff*`, `git blame*`, `git shortlog*`, `git rev-list*`, `git describe*`, `git tag*` (list), `git branch*` (list), `git status*`, `git whatchanged*`, `git ls-files*`, `git ls-tree*`, `git cat-file*`, `git reflog*`.
    - **DENY (default):** mutating — `git commit*`, `git push*`, `git pull*`, `git fetch*`, `git clone*`, `git merge*`, `git rebase*`, `git reset*`, `git checkout*`, `git am*`, `git apply*`, `git remote*` (write); AND credential-exposing — **`git config*`** (would read `http.<url>.extraheader` = the checkout token) and `git credential*`.
    - **CRITICAL — `.git/config` credential-read must stay closed (AGENT-03):** the finding was the agent reading the `actions/checkout` token (`http.<url>.extraheader`) from `.git/config`. **`external_directory: "deny"` does NOT block this** — `.git/config` is _inside_ the workspace (in-tree). And `cat*` is in the bash allowlist, so `cat .git/config` would otherwise be allowed. Two access vectors must be closed, defense-in-depth:
      1. **bash layer:** the permission pattern is the full command text (`source(node)`, `shell.ts:122`), matched by `Wildcard.match` (`*`→`.*`, anchored). Add **deny rules that win under `findLast`** (placed after the allow rules): `"*.git/config*": "deny"`, `"*.git/credentials*": "deny"`, `"*.git-credentials*": "deny"` — these match any command text touching those paths (`cat .git/config`, `head ./.git/config`, `grep x .git/config`). Plus `git config*: deny` and `git credential*: deny` (subcommand level) for the `git config --get …extraheader` vector.
      2. **read-tool layer:** the `read` tool raises its own `read` permission (`read.ts:228`) — independently deny reads whose path resolves to `.git/config`/`.git/credentials`/`~/.git-credentials` (a path-pattern deny on the `read` permission), so the credential can't be read via the read tool either.
      3. Consider also opencode's `Protected` mechanism (`file/protected.ts`) — evaluate whether registering `.git/config` there is cleaner than permission rules (architect call during story dev).
    - **Story 13.2 acceptance tests (mandatory):** `git log`/`git show`/`git blame` succeed in-tree; **`git config --get http.<url>.extraheader` denied**; **`cat .git/config` denied** (both bash and read tool); `git commit`/`git push`/`git clone` denied; a planted base64 checkout token in `.git/config` does NOT appear in the transcript (re-run of AGENT-03 must still PASS).
    - Consumers who genuinely need write git ops can add patterns via `bash_allow_patterns` (opt-in, same as bash).
  - **websearch = allow** (knowledge extraction needs it).
  - **webfetch = deny by default**, `allow_webfetch` input for coarse on/off. (No native per-domain allowlist — see Decisions note; trusted-domain webfetch deferred to a documented follow-up.)
  - **Fix the merge direction** (research fact #5, latent bug): OpenCode is _last-match-wins_; today's `{...defaults, ...existing}` lets consumer config weaken our hardening. Invert: apply consumer `permission` first, overlay Action security rules last so they win. **Revisit `handlePermissionAsked`** (opencode.ts:729 auto-replies `'always'`) — it must NOT silently re-allow a tool/command that config denied; an `external_directory` or denied-bash request must resolve to reject, not `'always'`.
- **A3 filesystem confinement via `external_directory: "deny"`** (REPLACES the weaker HOME/XDG relocation) — set the agent's project/working directory to `GITHUB_WORKSPACE` and `external_directory: "deny"` so any path outside the workspace (auth.json under `~/.local/share/opencode`, `/proc/*/environ`, `~/.aws`, `/etc`) is refused by opencode's own `containsPath` check (`tool/external-directory.ts`). This is the native, direct enforcement of the user's "only allow the working directory + tmp" — and it closes the on-disk credential reads (AGENT-02/03) that env-scoping alone cannot. **Preserve:** the workspace itself stays fully readable (that's the source the agent extracts knowledge from); `RUNNER_TEMP` writes are the Action's, not the agent's.
- **A4 non-root container** — Dockerfile: create `runner` user, drop privileges. **Decision: use the root→`gosu` drop pattern in `entrypoint.sh`** (research N1 "most robust") rather than a hardcoded `USER 1001`, for resilience across runner UID variance (self-hosted may be 1000). Pre-create + chown HOME/GOPATH/XDG so LSP autoinstall + auth still work. **Flag:** verify workspace + `$GITHUB_OUTPUT` writes still work (the documented UID pitfall) — funcval must confirm on a real container run.

### RC-B — baseURL credential exfil (CRITICAL; covers AGENT-04, FINDING-1)

- **B1** validation pass in `opencode.ts:buildSdkConfig`: for every `provider.<id>.options.{baseURL,endpoint}` in consumer config — require https, block private/loopback/link-local/metadata ranges, allowlist known provider hosts + `allowed_provider_hosts` opt-in input. Fail-closed (reject). Host list lives in `security.ts` as a small curated constant (NOT a provider-classification list — see D7 note).
- **B2** `opencode.ts:applyAuth` skips `client.auth.set` for any provider whose effective baseURL isn't allowlisted (fail-closed; key never leaves). **Preserve:** Azure `resourceName`→baseURL derivation; Bedrock/Azure host patterns in the allowlist; D8 (auth still from `auth_config`).

### MEDIUM-1 — global wall-clock timeout (covers FINDING-2)

Map `TimeoutError` reason → status `timeout` (distinct from `cancelled`). Preserve the signal path.

### MEDIUM-2 — job-summary phishing (covers AGENT-08)

- `summary-writer.ts`: replace `addRaw(scrubbed)` with `addCodeBlock(scrubbed)` (inert preformatted; neutralizes markdown links/images). Keep `scrubSecrets`+`truncateString`.

- `security.ts`: extend the mask/scrub set with secrets the Action _can_ enumerate — `GITHUB_TOKEN` if present + the values parsed from `auth.json` in `applyAuth` — and `core.setSecret()` them so they're masked in transcript/summary even if surfaced. Prevention (RC-A) is primary; this is the backstop (research C2). Conservative token-shape redaction (C3) optional, low priority.
